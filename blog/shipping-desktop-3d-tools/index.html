    Notes on shipping desktop 3D tools

    A field note on tube-and-pipe software: the model, the viewport, and the UI that operators actually trust.

    The viewport is not the product

    Desktop fabrication software looks like a 3D viewer. The work is the model underneath it: parts, bends, materials, and the SQL Server records that have to survive a bad save.

    Open Cascade and VTK draw the shape. WPF is where an operator decides whether the shape is believable. If the highlight, the selection, or the number on screen disagrees with the geometry, the tool is wrong even when the kernel is right.

    Ship the boring path first. A reliable round-trip beats a prettier viewport that loses the part.

    Most of the bugs I remember were not rendering bugs. They were agreements between the UI, the geometry kernel, and the database that drifted apart.
